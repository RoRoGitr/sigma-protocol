# Sigma Protocol — Claude Code Configuration

@AGENTS.md

**The single instruction surface for this repository is [AGENTS.md](AGENTS.md). Read it first and follow it.**

If only the import pointer is present in a nested session, read the repository-root `AGENTS.md` before acting.

Everything that defines the methodology lives there: the Steps 0–15 workflow (+ conditional 1.5 and 11.5), canonical sources (`steps/`, `commands/`, `src/`, `.agents/`), the execution backlog commands, HITL checkpoints, quality gates, and the execution standard. This file only adds what is Claude Code–specific.

## Claude Code runtime surfaces

| Surface | Purpose |
|---------|---------|
| `.claude/settings.json` | Hook wiring (department cascade, gates) |
| `.claude/hooks/` | Runtime hooks — `prompt-stack-augmenter.cjs` injects the department/step cascade |
| `.claude/agents/` | The 60+-agent department roster (13 departments) |
| `.claude/lib/agent-skill-registry.json` | The cascade registry: departments, agents, skills, step bindings |
| `.claude/rules/` | Reference docs: commands, workflow diagram, swarm orchestration |
| `.claude/skills/` | Operator-local skill overlay — generated by `scripts/install-claude-code.sh`, never tracked |

## Quick start

```bash
# One-time per machine: install skills + department composer
bash scripts/install-claude-code.sh
bash scripts/install-departments.sh

# Start the workflow
claude "Run step 1 ideation for [your product idea]"

# Invoke a department persona
claude "/marketing What's our positioning against [competitor]?"
```

## Slash surfaces

- **Steps:** `/step-0-environment-setup` … `/step-15-observability-contract` (+ `/step-1.5-offer-architecture`, `/step-11.5-task-handoff`) — canonical files in `commands/`.

## Local overrides

Put machine-specific or private instructions in `CLAUDE.local.md` (gitignored). Do not add project rules here — they belong in AGENTS.md so every runtime sees them.
