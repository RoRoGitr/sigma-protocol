# Game adaptation — Step 10: Feature Breakdown

Generated from catalog 1.0.0. Canonical source: `steps/step-10-feature-breakdown`.

Treatment: **adapt** — Feature shaping, appetites and PRD eligibility stay. Games shape systems (stealth, dialogue, crafting, traversal, combat) as features and content packs (acts, biomes, character sets, puzzle batches) as later features gated on system proofs. Each row is marked proof or volume. Decisions that stayed uninteresting after tuning are cut, not scheduled. Asset families get a level (hero, supporting, background) that decides how many gates they walk.

## Creator questions

- **systems-vs-content**: Which rows are systems that must be proven and which are content volume gated on those proofs?
- **asset-levels**: Which characters, spaces and audio families are hero, supporting or background, and which gates does each level skip?
- **cuts**: Which decisions or systems stayed uninteresting or unconnected after tuning and are cut?
- **appetites**: What time budget does each row get, and what is the smallest version that still serves its experience goal?

## reviewCriteria

- Asset levels are explicit
- Cuts cite the failed test

## revisionRules

- A failed proof re-opens every volume row gated on it
- A new system row must connect to existing mechanics or it is content
