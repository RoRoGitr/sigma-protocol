# Game adaptation — Step 2: Architecture

Generated from catalog 1.0.0. Canonical source: `steps/step-2-architecture`.

Treatment: **adapt** — C4, ADRs, quality attributes and trust boundaries stay. Game architecture additionally names the interaction model (authored beats, systemic possibility space, or hybrid), the simulation tick and authority model, the asset master store, the save model and, if the product requires it, online services. Engine and platform choice is an ADR with an exit criterion here, or stays open with a bounded bake-off experiment. Choosing an art mode (3D, 2D sprite, vector, text, audio-only, abstract, hybrid) is an architecture decision, not an assumption.

## Creator questions

- **interaction-model**: Is the game authored (scripted beats), systemic (connected rules producing second-order play), or a hybrid? Give one example of a class-to-class rule if systemic.
- **art-mode**: Which art mode does the product need: 3D, 2D sprite, vector, text, audio-first, abstract, or a mix? Why does the experience need that mode?
- **engine-decision**: Is an engine or framework already locked by the product or team? If not, what bounded experiment will decide it and what is the exit criterion?
- **simulation-authority**: Where does simulation truth live (single local process, host, dedicated server, turn server, none)? Is there real-time control of a body or object?
- **save-model**: What must persist between sessions, what must never persist, and how are old saves migrated?
- **online**: Multiplayer or online services: none, local, asynchronous, online. If online, which authority and cheat surfaces exist?

- Name the asset master store (DCC files, engine-native, sprite sheets, audio sources) and the interchange format
- Scope online and save models; mark multiplayer not-applicable with a reason when the answer is none

## reviewCriteria

- The interaction model is chosen with an example, not a label
- The art mode follows the experience goals and names the pipeline it implies
- Engine choice has an ADR or a bake-off with an exit criterion; no brand preference without one
- Multiplayer and save scope are answered, not defaulted

## revisionRules

- Changing the art mode re-opens every characters, environments and interface phase that assumed the old mode
- Changing the engine re-opens technical.version-pins, technical.interchange-contract and every engine-validation phase
- Changing the interaction model re-opens systems.class-to-class-rules and levels.solution-graph

## Sources and limits

- [Conversations From GDC Europe: Harvey Smith on systemic level design](https://www.gamedeveloper.com/marketing/conversations-from-gdc-europe-bill-fulton-zeno-colaco-harvey-smith) — verified-source-text. 2002 interview read. Deus Ex-era examples. Original GDC slides not recovered first-party. Production and QA cost of systemic design not quantified.
- [Would the Real Emergent Gameplay Please Stand Up? (GDC 2004)](https://www.gdcvault.com/play/1013560/Would-the-Real-Emergent-Gameplay) — source-claim. GDC Vault listing and an unofficial 2017 slide-plus-audio reconstruction; not frame-reviewed. Randy Smith's separate object-oriented level design essay was not found at a stable URL.
- [Game Feel: A Game Designer's Guide to Virtual Sensation](https://www.taylorfrancis.com/books/mono/10.1201/9781482267334/game-feel-steve-swink) — source-claim. Publisher pages and Library of Congress table of contents only; book body not read. Does not apply cleanly to turn-based, menu-driven or non-spatial games. 2008 input-hardware examples.
- [Lyra Sample Game in Unreal Engine](https://docs.unrealengine.com/lyra-sample-game-in-unreal-engine) — verified-source-text. Official docs extract. Unreal-specific. Sample version may lag engine (see G-UE-LYRA-VERSION). Full sample license not read.
- [godotengine/godot-demo-projects](https://github.com/godotengine/godot-demo-projects) — verified-source-text. README and LICENSE read. Demos are slices, not a production pipeline. Web builds are slower than native and not a ship oracle.
- [Saving games (Godot docs)](https://docs.godotengine.org/en/stable/tutorials/io/saving_games.html) — verified-source-text. Full page read by the research seat; URL reconstructed from the page title. Teaching slice, not a production save schema.
- [High-level multiplayer (Godot docs)](https://docs.godotengine.org/en/stable/tutorials/networking/high_level_multiplayer.html) — verified-source-text. Full page read by the research seat; URL reconstructed from the page title. Sample lobby code is not dedicated-server ready. HTML5 lacks some transport features.
- [Unity Boss Room co-op sample (Netcode for GameObjects)](https://github.com/Unity-Technologies/com.unity.multiplayer.samples.coop) — verified-source-text. Full README and license read by the research seat; URL reconstructed by the catalog author from the sample name, re-check. Unity Companion License, not MIT; Git LFS required.
- [Sigma Protocol game-development adaptation (architecture decision and integration contract)](../SIGMA-GAME-ADAPTATION.md) — proposed-adaptation. Our proposal, not an external practitioner method. Nothing here proves a game is good. Every phase's evidence must come from an authorized external experiment and a human review, never from the existence of a document.
