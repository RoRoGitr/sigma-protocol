# Game adaptation — Step 6: Design System

Generated from catalog 1.0.0. Canonical source: `steps/step-6-design-system`.

Treatment: **adapt** — Tokens, component styling and theming stay for menus and HUD. Games add gameplay-readability tokens (interactable, path, danger, focus, ally, enemy) and budget tokens that become acceptance numbers: triangle and texel budgets per asset class, material counts, atlas sizes, pixels per unit and palette limits for 2D, animation timing bands, audio loudness targets. Tokens for an art mode the game does not use are marked not-applicable with a reason.

## Creator questions

- **readability-tokens**: Which visual channels mark interactable, danger, path, focus and faction, and which channel backs up colour for each?
- **asset-budgets**: What are the per-class budgets: triangles or sprite size, texel density or pixels per unit, material or palette counts, atlas sizes? Write 'unknown until hardware class is chosen' where true.
- **timing-tokens**: What are the animation timing bands (attack windup, hit-stop, UI transition) and the audio loudness target?
- **not-applicable-tokens**: Which token families do not apply to this art mode, and why?

## reviewCriteria

- Every readability token has a non-colour backup
- Every budget is a number with a hardware class, or an explicit unknown with a revisit condition
- Contrast and silhouette tests are described, not assumed

## revisionRules

- Changing a budget re-opens every asset phase that cited it (geometry plan, UV, kit, atlas)
- Changing the hardware class re-opens all budgets

## Sources and limits

- [The Gamer's Brain - GDC talks and book record](https://www.youtube.com/watch?v=XIpDLa585ao) — source-claim. Talk metadata and transcript snippets; not frame-reviewed. Books not read. Neuroscience framing can be over-claimed if used as authority rather than as testable guidelines. Fortnite-scale UX org does not transfer to solo.
- [Xbox Accessibility Guidelines V3.2](https://learn.microsoft.com/en-us/xbox/accessibility/guidelines) — verified-source-text. Official Learn page read (v3.2 published 2023-06-08; page updated 2026-08). Xbox-example-heavy. Explicitly not a legal compliance checklist. Not every guideline body was fully read.
- [Accessibility Features (Steamworks Documentation)](https://partner.steamgames.com/doc/accessibility_features) — verified-source-text. Docs read. Tags are communication after features exist, not a design method. Wizard answers can be gamed. ESA Accessible Games Initiative tags may change the landscape.
- [Texel Density and Edge Padding - Polycount wiki](http://wiki.polycount.com/wiki/Texel_Density) — source-claim. Search extracts of the texel and edge-padding pages; URL reconstructed. Community numbers, not engine guarantees.
- [Topology - Polycount wiki](http://wiki.polycount.com/wiki/Topology) — source-claim. Search extract; community wiki, dated articles; URL reconstructed from the page title. Not an official engine standard.
- [glTF 2.0 add-on (Blender Manual)](https://docs.blender.org/manual/en/latest/addons/import_export/scene_gltf2.html) — verified-source-text. Full page read by the research seat; URL reconstructed from the page title. Real-time transmission support uneven; physics, lights and material animation do not export.
- [Sigma Protocol game-development adaptation (architecture decision and integration contract)](../SIGMA-GAME-ADAPTATION.md) — proposed-adaptation. Our proposal, not an external practitioner method. Nothing here proves a game is good. Every phase's evidence must come from an authorized external experiment and a human review, never from the existence of a document.
