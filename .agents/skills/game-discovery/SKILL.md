# Game Discovery

Open sibling gateway `../game-development/references/catalog.json`; in the author repo prefer `domains/game-development/catalog.json`. Select `discovery` plus the active canonical step and load its generated gateway reference. If absent, report the detailed pack missing and continue only ordinary discovery.

Order: record player experience/context → core verbs or decisions → intended mechanics/dynamics/aesthetic relationship → known constraints and rights → material uncertainties → smallest experiment and disconfirming result → review decision. Output a revisable discovery document and, if useful, an attributed idea pack.

Ask “What are we building?” only when the recorded domain is absent. Default to solo. Genre, engine, platform, monetization, multiplayer, deadline, and team size have no default. Do not require paper prototyping or outside testing; select a method that matches the uncertainty. Plan evidence is `PREPARED`; results stay `NOT-EXECUTED` without proof.

Sources: [MDA](https://users.cs.northwestern.edu/~hunicke/MDA.pdf); [Fullerton](https://www.gamedesignworkshop.com/). These support iterative experience framing, not a universal prototype rule.
