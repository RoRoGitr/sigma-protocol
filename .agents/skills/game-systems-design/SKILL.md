# Game Systems Design

Open sibling gateway `../game-development/references/catalog.json`, select `systems`, and load its workflow reference; prefer `domains/game-development/catalog.json` in an author checkout. Missing detailed pack blocks specialist process detail, not ordinary Sigma work.

Order: state player decision/input → state transition and constraints → feedback and failure/recovery → intended dynamic/aesthetic → progression, economy, or social rule only if applicable → assumptions and exploit/risk cases → smallest test and evidence → review/revision condition. Output a versioned systems document with dependency links.

Do not force an economy, progression tree, balance target, paper prototype, or external tester. A bounded test may run only under the existing task or external-harness authority; planning never presents a result as executed.

Sources: [MDA](https://users.cs.northwestern.edu/~hunicke/MDA.pdf); [Fullerton](https://www.gamedesignworkshop.com/). Preserve catalog source IDs.
