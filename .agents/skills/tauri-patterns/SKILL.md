# Tauri 2 Patterns

Production patterns for Tauri 2 desktop applications: project layout, typed IPC, capabilities/permissions security model, state management, auto-updater, sidecar processes, and packaging.

> Version anchor: @tauri-apps/api 2.11, @tauri-apps/cli 2.11. Verified 2026-06-04.

## When to Use

- Building a new Tauri 2 desktop application
- Wiring IPC commands between the Rust backend and the web frontend
- Auditing a Tauri 2 app's security model (capabilities, permissions, CSP)
- Implementing the auto-updater or sidecar processes
- Debugging native packaging issues

## When NOT to Use

- Tauri v1 — the capability model, plugin API, and `invoke` types changed substantially; v1 patterns are not compatible
- Pure web app without a desktop shell
- React Native / Expo mobile — use the `expo` skill

## Project Structure

```
my-app/
├── src/                    # Web frontend (Vite + React / Svelte / Vue)
│   ├── main.ts
│   └── ...
│
└── src-tauri/              # Rust backend
    ├── Cargo.toml
    ├── tauri.conf.json      # App metadata, bundle settings, plugins
    ├── capabilities/        # Permission grants per window/context
    │   └── default.json
    ├── src/
    │   ├── main.rs          # Entry point; registers commands + plugins
    │   ├── lib.rs           # App state; command implementations
    │   └── commands/        # One file per domain (auth.rs, fs.rs, etc.)
    └── icons/               # Platform icons (generated by tauri icon)
```

## Key Patterns

### Typed IPC command — Rust side

```rust
// src-tauri/src/commands/notes.rs
use serde::{Deserialize, Serialize};
use tauri::State;
use crate::AppState;

#[derive(Deserialize)]
pub struct CreateNoteArgs {
    title:   String,
    content: String,
}

#[derive(Serialize)]
pub struct Note {
    id:      String,
    title:   String,
    content: String,
}

/// Commands must be registered in main.rs via .invoke_handler(tauri::generate_handler![...])
#[tauri::command]
pub async fn create_note(
    args:  CreateNoteArgs,
    state: State<'_, AppState>,
) -> Result<Note, String> {
    let db = state.db.lock().await;
    let note = db
        .create_note(&args.title, &args.content)
        .await
        .map_err(|e| e.to_string())?;  // errors must implement ToString
    Ok(Note { id: note.id, title: note.title, content: note.content })
}

// src-tauri/src/main.rs
#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    tauri::Builder::default()
        .manage(AppState::new())
        .plugin(tauri_plugin_fs::init())
        .plugin(tauri_plugin_shell::init())
        .invoke_handler(tauri::generate_handler![
            notes::create_note,
            notes::list_notes,
            notes::delete_note,
        ])
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

### Typed IPC wrapper — TypeScript side

Never call `invoke` with raw strings. Wrap every command in a typed function. The wrapper is the single source of truth for argument/return shapes.

```ts
// src/lib/commands/notes.ts
import { invoke } from '@tauri-apps/api/core';

export interface CreateNoteArgs {
  title:   string;
  content: string;
}

export interface Note {
  id:      string;
  title:   string;
  content: string;
}

export async function createNote(args: CreateNoteArgs): Promise<Note> {
  return invoke<Note>('create_note', { args });
}

export async function listNotes(): Promise<Note[]> {
  return invoke<Note[]>('list_notes');
}

export async function deleteNote(id: string): Promise<void> {
  return invoke<void>('delete_note', { id });
}

// Usage in a component — never call invoke() directly here
import { createNote } from '@/lib/commands/notes';

async function handleSubmit(title: string, content: string) {
  const note = await createNote({ title, content });
  // note is fully typed as Note
}
```

### Capabilities and permissions

Tauri 2's security model is capability-based. Each window is granted only the permissions it needs. Default is deny-all.

```json
// src-tauri/capabilities/default.json
{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "default",
  "description": "Default capabilities for the main window",
  "windows": ["main"],
  "permissions": [
    "core:default",               // core IPC, window operations
    "fs:read-files",              // read specific directories
    "shell:open"                  // open URLs in the system browser
    // NOT "fs:write-all" unless this window needs to write
    // NOT "shell:execute" unless this window needs to spawn processes
  ]
}
```

Do not grant `core:all` or `fs:default` — grant only the specific permissions the window needs.

Custom command permissions (exposed via the Tauri plugin ACL):

```toml
# src-tauri/Cargo.toml — declare the plugin provides permissions
[package.metadata.tauri-plugin]
commands = ["create_note", "list_notes", "delete_note"]
```

### Managed state

Use `State<'_, T>` to share application state across commands. Wrap mutable state in `Mutex` or `RwLock`.

```rust
// src-tauri/src/lib.rs
use std::sync::Arc;
use tokio::sync::Mutex;

pub struct AppState {
    pub db: Arc<Mutex<Database>>,
}

impl AppState {
    pub fn new() -> Self {
        Self { db: Arc::new(Mutex::new(Database::open_default())) }
    }
}
```

```rust
// In a command — acquire lock for the minimum time needed
#[tauri::command]
pub async fn list_notes(state: State<'_, AppState>) -> Result<Vec<Note>, String> {
    let db = state.db.lock().await;
    db.list_notes().await.map_err(|e| e.to_string())
}
```

### Auto-updater

```rust
// main.rs — add the updater plugin
.plugin(tauri_plugin_updater::Builder::new().build())
```

```ts
// src/lib/updater.ts
import { check } from '@tauri-apps/plugin-updater';
import { relaunch } from '@tauri-apps/plugin-process';

export async function checkForUpdate(): Promise<void> {
  const update = await check();
  if (!update) return;

  // Show UI with update.version, update.body (release notes)
  // On user confirmation:
  let downloaded = 0;
  let total = 0;

  await update.downloadAndInstall((event) => {
    if (event.event === 'Started')    total      = event.data.contentLength ?? 0;
    if (event.event === 'Progress')   downloaded += event.data.chunkLength;
    if (event.event === 'Finished')   { /* update your UI state here */ }
  });

  await relaunch();  // restart to apply the update
}
```

Configure the update endpoint in `tauri.conf.json`:

```json
{
  "plugins": {
    "updater": {
      "endpoints": ["https://updates.your-app.com/{{target}}/{{arch}}/{{current_version}}"],
      "pubkey": "YOUR_PUBLIC_KEY_HERE",    // required — updates without signature verification are rejected
      "windows": { "installerArgs": [] }
    }
  }
}
```

### Sidecar processes

Sidecar = a binary bundled with the app and executed as a child process. Use for CPU-intensive work, language runtimes, or services that need process isolation.

```rust
// src-tauri/src/commands/worker.rs
use tauri_plugin_shell::ShellExt;
use tauri::AppHandle;

#[tauri::command]
pub async fn run_analysis(app: AppHandle, data_path: String) -> Result<String, String> {
    let output = app.shell()
        .sidecar("analysis-worker")   // binary name without extension
        .map_err(|e| e.to_string())?
        .args(["--input", &data_path])
        .output()
        .await
        .map_err(|e| e.to_string())?;

    if !output.status.success() {
        return Err(String::from_utf8_lossy(&output.stderr).into_owned());
    }
    Ok(String::from_utf8_lossy(&output.stdout).into_owned())
}
```

Register the sidecar binary in `tauri.conf.json`:

```json
{
  "bundle": {
    "externalBin": ["binaries/analysis-worker"]
  }
}
```

The binary must be platform-triple-suffixed (`analysis-worker-x86_64-apple-darwin`) in the `binaries/` directory.

### Content Security Policy

Set a tight CSP. Never use `unsafe-inline` for scripts.

```json
// tauri.conf.json
{
  "app": {
    "security": {
      "csp": "default-src 'self'; img-src 'self' data: asset: https://asset.localhost; style-src 'self' 'unsafe-inline'; connect-src ipc: http://ipc.localhost"
    }
  }
}
```

## Anti-Patterns

- Calling `invoke('command_name')` directly from component code — wrap in a typed function and call the wrapper
- Granting `core:all`, `fs:default`, or `shell:execute` without verifying the window actually needs them — follow least-privilege; start with the minimum and add only what is required
- Storing secrets in `tauri.conf.json` — they are bundled into the binary and readable by anyone with access to the app. Use the OS keychain (tauri-plugin-stronghold) or an environment variable set at build time
- Using `unsafe-inline` in the script CSP — allows XSS via injected script elements
- Building a Tauri 2 app with `tauri 1` command structure or `allowlist` config — the ACL / capabilities system replaced the v1 allowlist; they are not compatible
- Running expensive Rust work on the main thread without an async command — blocks the UI loop

## Quality Gates

- [ ] Every `invoke()` call in TypeScript goes through a typed wrapper function; no bare `invoke('command_name')` in component code
- [ ] Capabilities file grants only the minimum permissions required; no `core:all` or `fs:default`
- [ ] CSP is set; no `unsafe-inline` for scripts
- [ ] Mutable state is wrapped in `Arc<Mutex<T>>` or `Arc<RwLock<T>>`; locks held for minimum duration
- [ ] Sidecar binaries registered in `externalBin` and present as platform-triple-suffixed files
- [ ] Auto-updater `pubkey` configured; unsigned updates are rejected
- [ ] Secrets not stored in `tauri.conf.json`; OS keychain or build-time env var used instead
- [ ] Command errors return `Err(String)` (human-readable) — never panic in a command handler
