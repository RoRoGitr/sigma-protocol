# Game adaptation — Step 15: Observability Contract

Generated from catalog 1.0.0. Canonical source: `steps/step-15-observability-contract`.

Treatment: **adapt** — Per-feature instrumentation stays. Game events map to experience goals: first-session funnel, fail reasons, decision histograms (always-A detection), accessibility option usage, hitch and frame-time traces, animation and audio thread cost, GPU memory, shader permutations, save failures and, for online games, desync and disconnect. Provenance of shipped assets is part of the contract.

## Creator questions

- **goal-events**: Which events show whether each experience goal happened in real play?
- **decision-histograms**: Which decisions are instrumented so an always-A or random-pick pattern is visible after release?
- **performance-traces**: Which frame-time, memory, animation, audio and streaming traces are collected on the target hardware class?
- **accessibility-usage**: Which accessibility options are counted so tags and priorities reflect use?
