# Game adaptation — Step 14: Agent Runtime Bootstrap

Generated from catalog 1.0.0. Canonical source: `steps/step-14-agent-runtime-bootstrap`.

Treatment: **adapt** — Runtime context, skills and optional tracker dispatch stay. Game runtimes expose whitelisted local tool runners only (background DCC scripts, engine cooks, test runners, validators) and a playtest and receipt ingest path. Live editor bridges, community editor MCP servers and purchases stay off until a human enables them per project with a recorded decision. A failed playtest is a first-class artifact.

## Creator questions

- **tool-runners**: Which whitelisted commands may the runtime run (validators, cooks, exports, tests)? Which are explicitly forbidden (editor MCP, purchases, store uploads)?
- **evidence-ingest**: How do playtest logs, receipts and performance samples enter runtime memory and the tracker?
- **editor-bridge**: Is any live editor bridge enabled? If yes, who decided, on which isolated copy, and what is the rollback?
