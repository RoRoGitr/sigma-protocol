# Research adoption decisions

2026-09-22. Raw Grok/Claude reports are working research, not automatically the method. The canonical catalog and integration contract are the adopted specification.

| Research proposal or source limit | Adopted treatment | Reason |
| --- | --- | --- |
| “Demonstrated” sometimes means a PDF or README was read | Classify as verified source text or source claim; only inspected footage is observed footage, and no local engine tool is runtime-verified | Reading a description does not establish reproduction. |
| Universal paper prototype, outsider playtest or fixed pillar count | Choose the smallest experiment capable of testing the intended experience; external feedback is valuable when relevant and feasible | Real-time control, audio, spatial and narrative uncertainties need different media and participants. |
| Freeze all art/narrative until the core loop is proven | Lock only the costly commitments that depend on the uncertain premise; allow bounded art, narrative and technical tests | The Level Design Book explicitly distinguishes combat/spatial work from art/story-dependent experiences. |
| A metrics sheet is “invalid” until a capsule walks it | A proposed metrics plan is valid as a plan; measured metrics require engine evidence | Atlas can plan the test before execution. It cannot manufacture the measurement. |
| One 95/100 rubric and table shape for all nested work | Retain each canonical step’s actual verification schema and explicit review criteria | Scores never replace evidence or override stricter/different source contracts. |
| Film character/task-layer workflows | Reuse identity, topology, deformation and ownership concepts conditionally; add game import/runtime/budget checks | A production film rig or still render does not establish a playable asset. |
| Source-site audio mix numbers or broadcast standards | Treat as context-specific historical/source guidance; choose applicable platform, listening and accessibility targets per project | No one loudness/FPS/polycount/texture budget fits every game. |
| Third-party editor MCP capability lists | Candidate handoff adapters only; require pinned version, permissions, licensing, recovery and a bounded real test | No bridge was installed or executed by this research or by Atlas. |
| Single contributor/artifact treated as private | Independently authored, workspace-visible packs; explicit selected revisions and synthesis | Atlas does not implement contributor access controls. |
| Optional workflows created automatically | Show available methods, instantiate selected records on demand; unknown scope remains unresolved | Avoid manufacturing required scope or poisoning readiness with unused draft templates. |

## Parent-checked anchors

- Hunicke, LeBlanc and Zubek, [MDA paper](https://www.cs.northwestern.edu/~hunicke/MDA.pdf): a design/player-experience analysis framework, not a formula guaranteeing fun.
- Tracy Fullerton, [published playcentric excerpt](https://www.gamedeveloper.com/design/book-excerpt-game-design-workshop): experience goals, prototype, playtest and iterate. Full book not read in this task.
- Robert Yang and contributors, [level workflow](https://book.leveldesignbook.com/process/overview): tailor preproduction/layout/blockout/scripting/art/release to project needs.
- Microsoft, [Xbox Accessibility Guidelines](https://learn.microsoft.com/en-us/xbox/accessibility/guidelines): feature-scoped guidance, not a legal compliance certificate.
- Godot, [asset import](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/import_process.html): import metadata and exported behavior need separate checks.
- [Godot demo projects](https://github.com/godotengine/godot-demo-projects): match the sample branch to the selected engine version; browser performance is not native performance.
- [JetBrains Rider skills](https://github.com/JetBrains/rider-skills): semantic tooling requires actual Rider/MCP capabilities; source examples are not installed integrations.
- [Steam Playtest](https://partner.steamgames.com/doc/features/playtest): distribution/testing planning has its own platform setup. Nothing was published here.
- Julien Kaspar’s [Blender Studio workflow overview](https://studio.blender.org/training/stylized-character-workflow/): film-oriented training outline, not proof of a tested game asset pipeline. Paid lessons were not accessed.
- Emily Short’s [narrative structure comparison](https://emshort.blog/2016/04/12/beyond-branching-quality-based-and-salience-based-narrative-structures/): a lead for conditional branching/storylet comparison; apply only what the retrieved evidence supports.

Video evidence is recorded separately in CLAUDE-ENVIRONMENT-VIDEO-REVIEW.md and video-evidence/agent-runner/REVIEW.md. Timelapses, sample coverage, remaining defects and unobserved steps are explicit. Raw research contains additional leads and failed fetches; no universal practitioner ranking was adopted.

## Final skill simulation review

`CLAUDE-SKILL-EVALUATION.md` retains four full first-response simulations (solo puzzle, contributor synthesis, audio-only narrative and an unsupported images-as-rig/multiplayer-proof claim). It is a single-model, self-graded smoke review of bundled instructions, not invocation through an installed skill surface. The installed-skill evaluation briefs remain `NOT RUN`; no production effectiveness claim follows from their simulated scores.

Parent review adopted the actionable findings:

- F2: all nine planning skills explicitly list Write/Edit alongside their existing tools, matching document-authoring instructions. Host permissions and the planning boundary still apply.
- F3/F4: the gateway evaluation brief queues questions in catalog order, asks the first, and requires missing idea packs/revisions before attempting synthesis.
- F5: audio-role planning is reachable during Step 1. Interface readability, HUD and state phases include optional audio-first questions plus applicable review criteria. Existing saved documents remain valid because these added questions are conditional.
- F6: audio-only and card-based presentation no longer imply that environments are not applicable; navigable places and meaningful setting models determine scope.
- Final parent wording review: removed the blanket stranger/silent-facilitator playtest prescription and the arbitrary “this week” intake horizon. Participant fit, facilitation, bias and evidence are explicit decisions.

No response invented source packs, inspected unavailable character images, ran an engine, approved a journey gate, or claimed a tool integration worked. The raw evaluation describes the version it read; the changes above were made afterward and verified through catalog/mirror checks, actual UI rendering and the automated regression suite.
