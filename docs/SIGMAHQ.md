# SigmaHQ

SigmaHQ is your personal mission control for AI-assisted product development. It gives you a persistent kanban board, a mission system for multi-session goals, and a local dashboard — all stored at `~/.commandboard/` on your machine.

Sigma Protocol ships SigmaHQ as an installable component. It is not a cloud service. Nothing leaves your machine.

---

## Install

Run from the sigma-protocol repo root:

```bash
./scripts/install-sigmahq.sh
```

The script is idempotent. Run it on a fresh machine or re-run it to refresh an existing install. If `~/.commandboard/` already exists, use the runtime upgrade path first:

```bash
./scripts/install-sigmahq.sh --upgrade-runtime
```

That updates SigmaHQ scripts, docs, dashboard template, shared CLI, and runtime helpers while preserving local tasks, missions, dumps, schedules, stats, and settings.

If you want a full reset, pass `--force` to back up the existing install before replacing it:

```bash
./scripts/install-sigmahq.sh --force
```

The backup lands at `~/.commandboard.backup.{timestamp}`.

## First-Run Walkthrough

### 1. Bootstrap

```bash
./scripts/install-sigmahq.sh
```

After install, `~/.commandboard/` contains:

```
~/.commandboard/
├── board.md              -- Today's task board
├── week.md               -- Weekly view
├── backlog.md            -- Unscheduled tasks
├── config.yml            -- Board configuration
├── briefing.json         -- Dashboard data
├── dashboard.html        -- Dashboard template
├── dashboard-live.html   -- Generated browser dashboard
├── bin/
│   └── hq                -- Shared SigmaHQ CLI for Codex, Claude Code, and humans
├── sync-dashboard.sh     -- Refresh briefing.json + dashboard-live.html
├── install-daily-refresh.sh -- Install local 8 AM refresh scheduling
├── state-maintenance.py  -- Compact runtime files and recalculate XP/rank
├── ui-settings.json      -- Local theme/sidebar preferences
├── stats.json            -- Local XP/rank summary
├── stats-events.jsonl    -- Local XP event log
├── lib/
│   └── hq_state.py       -- Shared SigmaHQ state helpers
├── workspaces/
│   └── personal/         -- Default workspace + starter task
├── missions/
│   └── _schema/          -- Mission contract (JSON schema + templates)
├── dumps/                -- Brain dump inbox
└── archive/              -- Processed tasks and dumps
```

### 2. Open the Dashboard

```bash
# macOS
open ~/.commandboard/dashboard-live.html

# Linux
xdg-open ~/.commandboard/dashboard-live.html
```

The dashboard reads from local files generated by `sync-dashboard.sh`. Refresh it at any time:

```bash
hq sync --no-open
```

The sync command also runs the state maintenance pass. That pass keeps large runtime files compact, recalculates XP/rank from completed tasks, and preserves local UI settings. It does not upload anything.

Use the shared health check when Codex or Claude Code needs to verify the install:

```bash
hq health
hq health --json
```

### 2.1 Optional Daily Refresh

To rebuild the executive summary, schedule, calendar data, XP/rank, and dashboard every morning at 8 AM:

```bash
hq daily-refresh install --time 08:00
```

On macOS this installs a LaunchAgent at `~/Library/LaunchAgents/com.sigmahq.daily-refresh.plist`. On Linux it installs a user crontab entry. Logs go to `~/.commandboard/logs/daily-refresh.log`.

Remove it with:

```bash
hq daily-refresh remove
```

### 3. Create Your First Mission

A mission is a north-star outcome that persists across sessions. It answers: "what are we trying to accomplish, and when are we done?"

Inside Claude Code:

```
/mission new
```

Claude will ask for a title, success criteria, and deadline. The mission file lands at `~/.commandboard/missions/{slug}/mission.{json,md}` and activates for the current workspace.

Create a mission before starting Step 1 of Sigma Protocol. The mission system integrates with Step 0.5 — see [docs/missions/MISSION-SYSTEM-SPEC.md](missions/MISSION-SYSTEM-SPEC.md) for the full spec.

### 4. Create Your First Kanban Task

```bash
kanban-md create \
  --dir ~/.commandboard/workspaces/personal \
  --title "Start Step 1 for my product" \
  --status todo \
  --priority high
```

Tasks persist across sessions. Use `kanban-md` for all task tracking — not Claude's built-in `TaskCreate`, which is session-local and ephemeral.

For common task updates, use the shared wrapper so the dashboard, schedule, XP, and rank update right away:

```bash
hq tasks personal
hq move personal 1 doing
hq done personal 1
```

### 5. Dashboard Controls

The dashboard includes a local XP/rank panel, project leaderboard, theme switcher, and resizable workspace sidebar. These preferences are stored in `~/.commandboard/ui-settings.json` and browser local storage.

XP is derived from completed local tasks:

| Priority | XP |
|----------|----|
| critical | 175 |
| high | 125 |
| medium | 75 |
| low | 40 |

Run a maintenance-only refresh when you want to repair local state without opening the dashboard:

```bash
~/.commandboard/state-maintenance.py --all
```

## Codex and Claude Code Parity

SigmaHQ now has one shared command layer:

```
~/.commandboard local files
        ↓
hq CLI
        ↓
Codex skill/startup flow     Claude Code slash commands/hooks
```

Shared between Codex and Claude Code:

- `SIGMAHQ_HOME`, defaulting to `~/.commandboard`
- `hq` CLI
- `kanban-md` workspace task files
- generated briefing, schedule, dashboard, stats, and leaderboard files

Claude Code still owns Claude-native slash commands and SessionStart hooks. Codex uses the SigmaHQ skill plus the same `hq` CLI. Existing Claude installs remain compatible because `CLAUDE_CODE_COMMANDBOARD` is still set as an alias for `SIGMAHQ_HOME`.

## Architecture Overview

SigmaHQ stores everything in plain files under `~/.commandboard/`. There is no database, no cloud account, and no required background process.

```
~/.commandboard/
├── workspaces/{category}/{project}/   -- One directory per project
│   ├── tasks/                         -- Individual task files
│   └── config.yml
├── missions/{slug}/
│   ├── mission.json                   -- Machine-readable contract
│   └── mission.md                     -- Human-readable summary
├── missions/_schema/                  -- JSON schema + templates
├── missions/active/{workspace-slug}   -- Symlink to active mission
├── schedules/YYYY-MM-DD.{md,json}     -- Daily executive summary + time blocks
├── dumps/                             -- Unprocessed brain dumps
├── stats.json                         -- Current level, XP, rank, streak
├── stats-events.jsonl                 -- Local append-only XP event log
├── ui-settings.json                   -- Theme, sidebar width, collapsed sections
└── archive/                           -- Processed items
```

Workspace detection is automatic. Claude Code reads the current working directory and maps it to the correct workspace. The mapping table lives in `~/.claude/workflow.md`.

## Mission System Integration

Missions integrate with Step 0.5 of the Sigma Protocol workflow. Before starting Step 1 ideation, run `/mission new` to declare the north-star outcome for your product build. The mission becomes the ceiling above all PRDs, sprints, and kanban tasks for that workspace.

Key behaviors:
- Missions persist across compactions. The SessionStart hook injects a mission banner so Claude always knows the active goal.
- Halt oracle is tri-state: each success criterion evaluates to `pass`, `fail`, or `unknown`. Pass is latched — once a criterion passes, it stays passed.
- Human sign-off via `/mission complete` is required. The system never auto-completes a mission.
- `/dev-loop` terminates when the backlog empties OR when the mission halts.

Full spec: [docs/missions/MISSION-SYSTEM-SPEC.md](missions/MISSION-SYSTEM-SPEC.md)

## The 4 Shipped Methodology Skills

The install script copies 4 methodology skills to `~/.claude/skills/`. These are the skills most directly relevant to SigmaHQ workflows:

| Skill | What it does |
|-------|-------------|
| `decisions-patterns` | Enforces the `decisions.md` convention — every architectural decision gets a dated, reasoned record. Used inside missions and sprint cycles. |
| `gotchas-patterns` | Enforces the `gotchas.md` convention — captures non-obvious traps so future sessions don't repeat them. Especially useful when missions span weeks. |
| `sprint-patterns` | Covers parallel dispatch, reconciliation, and fan-out patterns. Invoked by the sprint execution engine (post-Step-14). |
| `prd-patterns` | Step 11 PRD generation methodology. Invoked when converting feature breakdowns into implementation-ready PRDs. |

These skills auto-load when their trigger phrases appear in conversation. See each skill's `SKILL.md` for the trigger list.

## Troubleshooting

**Missing dependencies**

The install script checks for `bash`, `python3`, and `kanban-md`. If `kanban-md` is missing:

```bash
npm install -g kanban-md
# then re-run
./scripts/install-sigmahq.sh
```

**Dashboard does not open**

`dashboard-live.html` is a static file generated from the dashboard template. If it opens blank, run:

```bash
hq sync --no-open
```

Then reload the file in your browser. The dashboard reads `briefing.json` from the same directory — if the file is missing or empty, the widgets render empty rather than erroring.

**How to reset**

Remove the install and start fresh:

```bash
rm -rf ~/.commandboard
./scripts/install-sigmahq.sh
```

If you want to preserve your tasks and missions before resetting, back them up first:

```bash
cp -r ~/.commandboard ~/.commandboard.backup.manual
```
